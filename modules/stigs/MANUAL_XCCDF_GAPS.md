# Manual XCCDF settings not represented in the STIG module

Generated by `tools/audit_manual_xccdf_gaps.ps1` from the manual XCCDF files in `ansible/`.

## Scope and interpretation

A rule is listed when its exact DISA `V-` identifier does not occur in either `modules/stigs/manifests/*.pp` or any asset below `modules/stigs/files/`. The requirement title and concrete targets are taken from that rule in the manual XCCDF. This is a conservative traceability gap report: a setting may exist incidentally without its `V-` identifier, but it is not represented as an implemented control and requires review. The repository cross-check calls out exact configuration lines from the XCCDF fix text that do appear elsewhere in the module; those rows are traceability or release-applicability questions rather than proven missing directives. Conversely, controls whose identifiers appear in the module are outside this report; this audit does not prove that those implementations are complete or compliant on a deployed host.

Package and service maps that are guarded away from an OS do not count as implementation for that release unless its `V-` identifier is explicitly represented. Site-specific, hardware-dependent, partitioning, runtime-inventory, and manual-review requirements remain listed because the current static files and manifests do not express them.
